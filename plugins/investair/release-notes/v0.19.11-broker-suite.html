Architecture

How it works

Each broker user owns three private Claude artifacts published to their claude.ai account. The artifacts are HTML pages that declare the Investair_data MCP connector plus the db and user runtime capabilities. All live data is fetched at view time through the connector — there is no Investair backend serving these pages; the Claude artifact runtime handles auth and data access.

Template System

Slot-fill pattern

The three dashboard HTML templates live in the plugin's skills/broker-setup/artifacts/ directory. At setup time, a Python script performs exact string substitutions (named slots) in each template before publishing. No DOM manipulation or server-side templating — plain string replace.

The overwrite path (re-running setup for an existing firm) reads the current slot values back from the published artifact HTML to avoid asking the user for data already captured.

Setup Skill

/broker-setup — execution flow

1

Find template directory

find ~/.claude/plugins -name "pipeline-template.html" -path "*/broker-setup/artifacts/*". Stores TMPL_DIR. Stops if not found.

2

Collect firm name — plain text, no AskUserQuestion

Critical ordering fix: firm name is collected via a plain conversational message before any artifact listing. This prevents broker names from leaking into Claude's context and appearing as pre-populated options. Stores FIRM_NAME.

3

Check for existing artifacts

Artifact({ action: "list", scope: "mine", limit: 50 }). Looks for titles matching "Sweet Spot Pipeline", "Company Page", "Standardised Reports". If found: AskUserQuestion overwrite vs keep-alongside. Overwrite path reads existing artifact HTML to extract BROKER_CANONICAL and other slot values, skipping redundant questions.

4

Optional preferences — AskUserQuestion with fixed options

Two questions: (1) multi-select sectors up to 3 (Gold / Copper-Battery Metals / Oil & Gas / Other) → SECTORS[]; (2) house stocks (ASX codes) → HOUSE_STOCKS[]. Options are hardcoded in SKILL.md — Claude cannot generate its own options or pull firm names from memory.

5

Broker canonical lookup

Single LIKE '%KEYWORD%' query against Broker.deal_broker_map. Keyword derived from FIRM_NAME by stripping common suffixes (Securities, Capital, Ltd, etc.). Confirms match with user in one line. If no match, proceeds with FIRM_NAME unvalidated — pipeline sweet spot won't be derived from deal history. Stores BROKER_CANONICAL and BROKER_CANONICAL_ID.

6

Auto-generate coverage list

describe_table('Placement.deals_daily') to discover column names, then query lead/co-lead raises for the past 24 months filtered by BROKER_CANONICAL_ID. Returns up to 50 ["TICKER","Company name"] pairs → COVERAGE.

7

Publish 3 artifacts

Python slot-fill → publish each artifact with full capability declarations. After Pipeline publish, writes initial config/screen doc to artifact database via ArtifactData if SECTORS or HOUSE_STOCKS non-empty.

8

Pin + auto-schedule

Pins all 3 artifacts. Calls mcp__scheduled-tasks__create_scheduled_task with cronExpression: "0 7 * * 1" (Monday 7am local), taskId investair-pipeline-{firm-slug}, and a fully self-contained prompt embedding FIRM_NAME, BROKER_CANONICAL, PIPELINE_URL. If creation fails, provides a 2-line fallback text.

Scheduled Task

Weekly pipeline — runtime flow

Each Monday at 7am a fresh Claude session runs with the self-contained prompt. No memory of setup. The prompt includes the pipeline artifact URL, broker canonical name, and firm name. The session:

  1. Reads config/screen from artifact database — sector and house stock overrides set by the broker from within the dashboard UI.
  2. Calls screen_funding_risk / screen_cashflow on Investair_data to find ASX companies with 4–10 weeks confirmed cash runway.
  3. Derives the broker's sweet spot from last 12 months of deal data (top sectors by deal count, core market-cap band). Applies saved overrides on top.
  4. Forces house stocks into the WATCH list regardless of runway.
  5. Calls list_announcements on top 25 candidates (last 45 days) to filter out active raises, halts, placements, takeovers.
  6. Reads weekly/latest from artifact database (previous week's results).
  7. Writes new results to weekly/latest: { date, conf, watch, summary, prev }.
  8. If conf or watch changed, sends a brief summary message. Otherwise skips.
Bug History & Fixes

Setup skill — what broke and why

  • Fix

    Broker name pre-population in AskUserQuestion

    Root cause: The skill listed existing artifacts before asking for the firm name. Artifact titles contained broker names (e.g. "MST Financial Sweet Spot Pipeline"). Claude extracted these names into AskUserQuestion options because the tool schema requires 2–4 options — Claude generates them from whatever is in its context. No instruction to avoid this was sufficient while the names were in context.

    Fix: Firm name is now collected as a plain-text message in Step 2, before any artifact listing. Step 3 (artifact check) only runs after FIRM_NAME is established. The AskUserQuestion calls for preference questions use fully hardcoded options specified in SKILL.md.

  • Fix

    Skill edits overwritten by marketplace refresh

    Root cause: The marketplace is a git clone of github.com/Investair-com-au/investair-claude-marketplace. When CoWork starts a new session it refreshes (pulls) the marketplace from GitHub. All local edits to SKILL.md were uncommitted — every marketplace refresh overwrote them with the GitHub version. Additionally, CoWork maintains its own extracted plugin copy in local-agent-mode-sessions/{session-id}/rpm/plugin_{id}/ that must also be synced manually per session.

    Fix: All skill changes are now committed and pushed to the GitHub repo. Standard git add → commit → push after every SKILL.md edit. Manual CoWork copy sync still required for in-flight sessions.

  • Fix

    hooks.json format error

    Root cause: Event names were at the root level of the JSON object. Expected format is {"hooks":{"SessionStart":[...]}}.

    Fix: Wrapped event entries in a "hooks" key. Validated via PublishPlugin which rejects with a descriptive error.
